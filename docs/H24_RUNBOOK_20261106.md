# H24 — runtime contract and first controlled pilot (2026-11-06)

## Branch state

Draft PR #174, stacked on P2/H22. H24 is an **opt-in** model family and
trainer switch; ordinary H16/H17/H18/H22 parameterization and checkpoint
decoding remain separate. H24 changes the **Act-clear** critic only; the
geometric shaped future-HP critic, H21 policy object graph and local PUCT
algorithm remain structurally as before. The default PUCT value uses the
shaped future-HP critic (\`--h24-search-act-mix 0\`).

The value critic uses a second H21 encoding of the public state with a
**canonical single fixed action**, canonical HP=1, gold=0, and any
mechanics-certified potion identities removed with their occupancy/empty
slot counters recomputed. All ordinary relics, unapproved potions, deck,
combat state, map and other context remain visible. This isolates the
resources whose coefficients must be nonnegative. The full H21 actor
continues to receive all original objects and legal actions.

Default selection:

    ResourceConstraintSelection(hp=True, gold=True, potion=True, relic=False)

The certified potion vocabulary starts empty; relic constraints have no
value head channels and are disabled even if an external human/mechanics
receipt is supplied. \`--h24\` currently exposes **HP+gold** constraints.
There is no rarity-derived relic authorization.

## Mathematical scope

For any two valid states whose canonical value encodings are exactly equal
(including token identities, numbers, owners, typed relations and action
anchor), and with all nonselected resource coordinates held fixed,

    HP_1 <= HP_2, gold_1 <= gold_2
    ==> sigmoid(L(z, HP_1, gold_1)) <= sigmoid(L(z, HP_2, gold_2)).

The nonnegative softplus weights make this exact, modulo floating-point
roundoff, at every optimizer step. Adding certified potion/relic coordinates
requires explicit whitelist and training schema changes; item names alone
are not a mechanics proof.

**Scope limit:** monotone in numeric features is a structural statement.
Its *game-theoretic applicability* still requires G1–G6/H1–H3/D1–D3 and
source-backed exclusion/coupling checks from
\`docs/H24_PREDICATE_VERDICT_20261106.md\`.
HP-dependent items such as Meat on the Bone, adverse gold triggers, and
event- or inventory-dependent potion interactions need explicit audits.
This prototype has no automatic global context-specific safety switch.
The first experiment therefore tests a research prior; production-wide
mechanics-sound activation is contingent on that audit.

## What is wired

- \`tools/train_h24_hard_resources_a0.py\` requires \`--initial-h22\`.
- Generic pilot accepts the opt-in \`--h24\` flag only with H21 + H22
  initialization; its fingerprint and model schema are H24-specific.
- \`H24JointActPilotNet.warmstart_h22\` copies the H22 backbone, policy,
  shaped-HP critic and Act-clear base parameters. The neutral-value
  encoder and positive coefficient channels are newly initialized.
- \`JointActPilotNet.load\` routes a versioned H24 checkpoint to the H24
  constructor, without relaxing H22 checkpoint schema validation.
- H24 decision encoding and dual collation are supported for both worker
  CPU inference and the shared actor (reference/packed/fixed-shape).
- The existing joint loss and H17 replay train the new Act-clear critic
  and the unchanged other heads, including through shared backbone
  gradients.
- The second encoder pass adds substantial inference cost and must be
  benchmarked before a long experiment.

## Bounded smoke, fish shell

Use the **actual local trained H22 R95 checkpoint** and your pinned
emulator revision. These paths are illustrative; verify your local source.

    cd ~/projects/sts2-ai
    set emu ~/projects/sts2-emulator
    set rev (git -C $emu rev-parse HEAD)
    set h22_r95 /path/to/trained-H22-R95.pt
    set macro results/nature/h6c-macro-attention-r80.json

    python -u tools/train_h24_hard_resources_a0.py \
      --initial-h22 $h22_r95 \
      --emulator-root $emu --emulator-revision $rev \
      --macro-model $macro \
      --output-root results/h24-hp-gold-smoke \
      --rounds 1 --runs-per-round 1 --heldout-runs 1 \
      --workers 1 --device cpu --actor-device cpu \
      --actor-fixed-shape-batch-size 2 --actor-max-batch 2 \
      --simulations 8 --search-depth 2 --max-searches 1 \
      --execute

Do this only after H24 CPU CI, then validate the resulting progress
record and actual search transitions. In CI, a synthetic model/actor
suite tests initialization, exact context parity, training/replay
gradients, checkpoint roundtrips and local/shared inference.

## Matched learning pilot

Compare the following at the **same trained H22 R95 source**, identical
emulator revision, seeds, worker count, map, search budget, terminal
outcome target, actor search mode and equal completed training episodes:

1. H22 control using \`tools/train_h22_h21_generated_a0.py\`,
   \`--initial-h22 $h22_r95\`.
2. H24 HP+gold using \`tools/train_h24_hard_resources_a0.py\`,
   \`--initial-h22 $h22_r95\`, \`--h24-search-act-mix 0\`.

Both arms: 5 rounds × 64 completed-episode target, 16 held-out per
round, 15 workers; independent 32–64 seed audit after selecting a
checkpoint. Use distinct output roots. R95 selection cohort is
**not** the final held-out evaluation set.

Report: actual completed episodes, clear rate and uncertainty, boss
reach, floor distribution, boss damage, gold/spend/potion behavior,
Act-clear calibration and categorical BCE, value-counterfactual
violations, shared actor time and emulator transitions/sec. Include
censored counts. In particular, measure the H24 dual-encoder overhead
before committing six hours to training.
