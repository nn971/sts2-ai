# Information policy

## Three distinct objects

The project distinguishes:

### Engine state

Complete continuation-relevant state used by the emulator, potentially including hidden RNG and internal histories.

### Observation

Information legitimately available to an agent under a declared policy.

### Belief state

The agent's representation of uncertainty over hidden engine states compatible with its observation/history.

These should never be conflated.

## Fair-agent default

The eventual primary benchmark should approximate information available to a skilled human player under the chosen game rules and UI, including deterministic deductions that a human could in principle track.

The exact policy must be versioned because questions such as seed visibility, deterministic RNG exploitation, retained history, and hidden counters can affect what counts as legitimate information.

## Oracle mode

An oracle experiment may expose hidden RNG or full engine state. This is useful for:

- measuring the value of future knowledge;
- debugging search;
- deriving upper bounds;
- isolating strategic errors from uncertainty errors.

Oracle results must never be compared with fair-agent results without a clear label.

## Data leakage

Training examples generated by an omniscient search may leak hidden future information even if the model input later hides RNG. The target-generation procedure therefore needs its own information-policy metadata.

For fair training, strategic targets should integrate over hidden states/beliefs rather than condition on the one hidden future that happened to be present in the trace.

## Version key

Every experiment/data record should eventually include something like:

```text
information_policy = "fair-v1"
```

or:

```text
information_policy = "oracle-full-state-v1"
```


## Current prototype fair projection

The pinned prototype emulator exposes `prototype-fair-v0`. It includes the persistent deck,
relics/potions, complete generated map graph, visible combat zones, enemy intent/status/powers,
reward/shop/event state, and legal actions. It deliberately omits emulator RNG state, run seed,
and hidden draw-pile order.

This policy is provisional and must not be conflated with a verified native STS2 information
model. It gives early AI experiments a disciplined non-oracle boundary while fidelity work is
still pending.
