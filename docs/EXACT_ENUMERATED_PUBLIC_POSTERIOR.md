# Exact full-public-history posterior over an enumerated seed universe

**Research status:** mathematically exact, fully simulated **finite-prior game
model**, not an approximation or proof of the native game's seed law.

`ExactFiniteSeedPosteriorSampler` makes the whole-run public-history
conditioning problem fully testable by declaring a *finite prior support*
up front: a sequence of distinct unsigned 128-bit seed atoms. A run under
this experimental prior uniformly selects one of the declared atoms,
represented in the deterministic prototype emulator as
`belief-pool:<32-digit-hex>`.

For any sequence of public observations/legal menus and player actions
`h`, let the support be `U={s_1,...,s_N}` and let `H(s_i)` be
the full visible transcript produced by replaying those actions from
`s_i`. The exact posterior is

\[
 P_U(S=s_i\mid H(S)=h)=
 \begin{cases}
   1/m_h,&H(s_i)=h,\\
   0,&\text{otherwise},
 \end{cases}
 \quad m_h=\#\{s_i:H(s_i)=h\}.
\]

The exact conditional probability of the observed **public outcomes under
the specified player action sequence** is `m_h/N`. Player decisions are
conditioned-on interventions here, not random events requiring a policy
model. An unknown action/menu, observation mismatch, unsupported seed,
or zero posterior support raises explicitly. No hidden real-game run seed
is consulted.

This model differs fundamentally from the older
[finite IID cohort](INCREMENTAL_FINITE_BELIEF.md). In that sampler, the
finite cohort is a *Monte Carlo draw* from a larger intended 128-bit
ensemble, and survivors are only the posterior of the sampled empirical
cohort. Here, the enumerated finite support **is itself the entire
specified prior**. Enumeration is complete, not approximate. Sampling
survivors with replacement gives independent, correct conditional
transitions under that model, and stochastic PUCT can use them without
pretending its seed observations are native-game draws.

## How to use

```python
import random
from sts2_ai.emulator.exact_finite_posterior import ExactFiniteSeedPosteriorSampler
from sts2_ai.search.fair_replay import FairReplayPuctAdapter
from sts2_ai.search.puct import StochasticPuct

# Build public_history using ONLY visible Observation, chosen LegalAction
# and complete visible legal action menus for every decision.
# No real-game exact state, seed, RNG cursor or canonical hash is supplied.
universe = tuple(range(128))  # deliberately tiny *alternate game prior*
with ExactFiniteSeedPosteriorSampler(
    backend, seed_values=universe
) as posterior:
    posterior.initialize_history(public_history)
    print(posterior.posterior_support_size)
    print(posterior.evidence_probability)
    root = FairReplayPuctAdapter(
        backend, sampler=posterior, goal="prototype-act1-clear-v1"
    )
    frame = root.root(public_history, public_history[-1].legal_actions)
    result = StochasticPuct(
        root, max_depth=128, seed=2026
    ).search(frame, simulations=8)
```

This example requires an already-opened emulator `backend` and a previously
collected complete `public_history` with legal menus; it can exhaust PUCT's
depth cap, in which case it must fail closed. Only use the terminal outcome
labels when a run really reaches the objective.

Unlike the rejection sampler, full enumeration guarantees no rejection
exhaustion for any public trace generated by a seed **in the declared
finite support**. The implementation retains all matching hypothetical
states and advances them once per observed action, rather than restarting
them for every PUCT simulation. Sampled forks are released by the caller
(or automatically by the fair PUCT lifecycle).

## Performance and applicability

- Initial cost: `N` simulated resets. Conditioning through `L`
  observed decisions requires at most `N*L` simulated transitions,
  with early elimination of mismatched seeds.
- Storage: `O(m_h)` complete simulated states after filtering.
- Independent search rollouts: one cheap fork of a uniformly selected
  surviving state per simulation, maintaining correlations throughout
  future RNG events.
- Exact posterior evidence probability: `m_h/N`, *not* an estimator.
  As evidence accumulates, the support may collapse to one seed. That
  zero-uncertainty artifact is characteristic of a small discrete prior,
  not of native STS2.
- A public map from a **real/native run** may have no atom in a small
  enumerated prototype prior. Zero support does not mean the public
  observation is impossible under the native game. No fallback is allowed.

A pinned JSONL integration regression follows a public
`RunStart -> MapChoice -> Combat` history generated by one declared
atom. It checks that this atom cannot disappear, that the posterior
matches all three full public frames and their complete legal menus,
and that independent continuations can be sampled. Synthetic tests
enumerate conditional likelihoods analytically and compare against
PUCT estimates of correlated future outcomes.

## Scope and next milestone

This enables **honest, teacher-free, small-prior end-to-end search
experiments** in a declared discrete alternate game. It does **not**
calibrate the true native chance distribution, nor provide a scalable
posterior for arbitrary natural STS2 runs. The separately introduced
[local combat-stream conditioner](LOCAL_COMBAT_STREAM_BRIDGE.md) preserves
some room-entry stream correlations but also lacks the complete prior.

Next prioritize *structured posterior factorization* that allows
conditioning maps, encounters, card draws and reward streams without
enumerating entire seeds. Such factorization must be justified by
a versioned chance model, and audited for which public observations
constrain which latent events. Never splice independent streams if
their joint law is correlated by the actual simulator.
