# Datasets and corpora

We expect several qualitatively different corpora.

## 1. Truth corpus

Produced from native-game/parity instrumentation, primarily maintained by `sts2-emulator`.

Conceptually:

```text
(S, action, S_native')
```

Used to verify mechanics. It is not a strategic training target by itself.

## 2. Search corpus

Expensive counterfactual analysis generated by `sts2-ai`:

```text
root state / observation
legal actions
search statistics
child outcomes
value estimates
policy targets
provenance
```

This is the persistent strategic evidence layer.

## 3. Training corpus

Compact examples distilled from search evidence, for example:

```text
(observation, pi_search, V_search)
```

or other supervised/RL targets.

### Current training export

The parent repo can now distill persisted search evidence directly:

```fish
sts2-ai export-training results/strategy.sqlite results/train.jsonl \
    --search-version '<exact search configuration>' \
    --min-budget 128
```

By default the exporter keeps the strongest matching search budget for each exact state
and provenance tuple. `--all-budgets` retains every matching budget for diagnostic
datasets.

Each JSONL record contains the player-facing observation payload, normalized root visit
distribution, per-action kind/payload/search value/visits, a root value target, and search
provenance. The value target is the best visited root-action mean. Exact state hashes are
retained only as source provenance; they are not part of the player-facing model input.

This first export deliberately preserves the search regime label. Current targets are
usually `oracle-exact`, so future fair-model experiments can distinguish oracle-derived
supervision from genuinely fair search evidence.

## 4. Scenario archive

Strategically important states deliberately retained for repeated study:

- policy/search disagreement;
- high model uncertainty;
- rare relic/card interactions;
- close shop/path/card decisions;
- low-HP survival situations;
- unusual decks;
- boss relic choices;
- historically misplayed states.

The scenario archive prevents training from spending nearly all compute rediscovering ordinary early-run positions.

## Storage policy

Large data does not belong in Git. Git stores:

- schema definitions;
- small fixtures;
- dataset manifests;
- checksums;
- generation configuration;
- provenance.

Actual corpora should live in local/object/distributed storage selected later.

A manifest should record at least:

```text
dataset_id
created_at
ai_commit
emulator_commit
game_build
information_policy
generator/search/model versions
record count
content checksum/storage URI
```
