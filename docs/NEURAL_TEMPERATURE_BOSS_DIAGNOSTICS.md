# Native neural policy temperature & Act-1 boss diagnostics (v1)

**Purpose:** diagnose why the trained neural policy reaches deep Overgrowth
when evaluated greedily but the T=1 categorical training policy usually dies
early. All decisions are from public observations and the legal-action menu;
the emulator privately owns game RNG and exact state. This is an
**inference-only** experiment: optimizer, training checkpoints, learning rate,
entropy coefficient and REINFORCE sampling distribution are unchanged.

## Input

Use the exported portable neural model from the 240-episode pilot.
`results/native-round20-model.json` was generated by
`tools/train_selfplay.py --resume --rounds 20`; the original optimizer
checkpoint is `results/native-fixed-train.pt`.

On CachyOS with fish:

```fish
git pull --ff-only
git submodule update --init --recursive
source .venv/bin/activate.fish
python tools/diagnose_neural_policy.py \
  --model results/native-round20-model.json \
  --report results/native-temperature-diagnostics.json \
  --environment native-overgrowth \
  --runs 64 \
  --temperatures 1 0.5 0.25 greedy \
  --max-decisions 4096 \
  --max-boss-actions 48
```

For a smaller first pass, use `--runs 16`. The default seed prefix
`selfplay-heldout` gives the exact same 0–63 held-out seed names as
`native-round20-report.json`; the greedy result should reproduce its
mean frontier progress **10.127566558851909** if the model and emulator pin
match.

## Policy definition and fair replay

- Greedy: the existing `NeuralGreedyAgent`, including its action-ID tie-break.
- T=1, 0.5, 0.25: sample exactly from
  `softmax(public_legal_action_logits / T)`, with stable centering,
  finite-logit checks, and deterministic per-seed sampling RNG.
- All four policies share game seed strings. Finite-temperature policies
  additionally share one reproducible *sampling random stream* per model and
  game seed, **not a leaked emulator RNG state**. Once their decisions
  diverge, the game's internal chance draws may differ, so pairing supports
  comparative analysis rather than asserting identical chance paths.
- No external teacher, hidden seed feature, exact-state fork, or
  hypothetical game action is exposed to the neural policy.

## Report: what to inspect

`summary` gives per-temperature completed/censored games, wins,
mean frontier progress, Act-1 clear count, boss-floor reaches,
boss-combat entries/defeats, mean selected-action probability, mean
maximum-action probability, mean normalized policy entropy and action-kind
counts. Entropy is normalized by `log(number_of_legal_actions)`; zero for
single-action menus or deterministic greedy policies.

`paired_completed_only` compares sampled temperatures with greedy on
matched seeds and excludes either censored outcome.

`runs` contains compact per-seed public summaries: terminal floor/outcome,
HP before the terminal transition, last selected action kind, latest
public combat snapshot on defeats, and a bounded first/last trace of
floor-16 combat decisions. Boss traces include visible enemy names/HP/intents,
player HP, combat turn when available, selected action kind/action ID,
legal-menu size, action probability and entropy. Stored traces are clipped to
at most eight first and `--max-boss-actions` last decisions for each fight.

The program **does not identify the tactical cause of a death automatically**.
Comparing the final turns and HP/enemy states with the initial boss state is
an evidence-gathering step, not a source-fidelity or optimality assertion.

## Decision rule for next development

1. If reducing T sharply improves sampled survival and decreases
   normalized policy entropy, evaluate an explicitly on-policy training
   temperature schedule as a **new training version** with matching
   `log_softmax(logits / T)` gradients and revised checkpoint fingerprint.
   Merely sharpening the rollout actor while optimizing a T=1 policy
   gradient would be mathematically inconsistent.
2. If all sampled temperatures (including T=0.25) lag greedy, inspect
   concentrated late-game failure actions and value estimates, rather than
   scaling episode count blindly.
3. If greedy floor-16 boss runs all fail with similar public combat
   snapshots, investigate combat strategy, resource allocation, and the
   emulator's model fidelity before asserting a learning limitation.

Current results from the 240-episode pilot: greedy policy averages
10.13 frontier progress over 64 held-out games versus heuristic 7.82;
12 greedy runs reach floor 16 but no Act-1 clears or full victories have
been observed. The purpose of this diagnostic is to resolve what to
change next, not to infer that a particular temperature will improve play.
