# Factored RunStart posterior under an explicit independent-stream prior

This is the first **structured, exact posterior without enumerating
complete run seeds** in the research AI. It applies **only to the start
of a run**, just after `start_run` reveals the Act 1 map and boss.
It is *not* an exact model of native STS2 RNG.

## Declared alternate prior

The pinned emulator revision
`11a562b141bf0fb5186448eb7a33c4dbe00be2b4` adds
`prototype-independent-initial-streams-v1`. Instead of deriving all six
SplitMix64 streams from a common run seed, the experimental run selects
**independent** 64-bit initial stream states. Under this alternate prior:

- `map` is uniform over a declared finite set `M`.
- `combat` is uniform over a declared finite set `C`.
- `combat_targets`, `event`, `reward`, `shop` are independently
  uniform on all 64-bit initial states.

The trial game is generated by setting those independent states **before
any RNG call**, then executing the engine's ordinary `start_run` action.
It is a reproducible, fully specified different stochastic model.
The native seeded game's joint stream prior is **not** assumed to
factorize.

At that exact boundary, the engine consumes `map` for the map graph
and `combat` for the preselected Overgrowth boss. Other streams
are not consulted. Tests in `sts2-emulator` verify this dependency
graph by changing each stream and comparing full public observations
and complete legal menus.

For the visible map and boss `(m,b)`, the prior permits an exact
factorization:

\[
\Pr(U_M=u,U_C=v\mid m,b)
 =\Pr(U_M=u\mid m)\Pr(U_C=v\mid b).
\]

The four unused streams retain their independent uniform priors.
No independence claim is made for later game states, when events
and mechanics may combine stream-dependent information.

## Implemented sampling

`FactorizedRunStartPosteriorSampler` accepts **only** a complete
public history consisting of two frames:

1. `RunStart` observation, `start_run` chosen action, complete legal menu.
2. Resulting `MapChoice` observation with revealed map/boss, complete
   legal menu, and no chosen action.

It enumerates `|M|` candidates with a fixed reference combat stream
and `|C|` candidates with a fixed reference map stream, checking
the complete public observation **except for the boss** on the map
side, and the boss identity on the combat side. It also checks
the full map-choice action menu. The accepted sets are retained
as separate independent posterior factors.

Each search continuation draws a map atom and combat atom uniformly
from the survivors, draws each other stream as a fresh uniform
64-bit state using the *search-side RNG*, and calls
`reset_factorized_hypothetical` followed by the ordinary
`start_run` game action. The resulting full emulator state
already has correctly advanced RNG cursors for all six streams.
Before returning it, the adapter verifies the **entire** public
observation and legal menu exactly match the recorded history.

There are no oracle forks from a real run; the live seed is never
supplied to the sampler. The operation is compatible with the existing
`FairReplayPuctAdapter` solely for this **declared alternative prior**.

## Performance and evidence probability

- Conditioning cost: `O(|M|+|C|)` one-step emulator replay
  candidates, instead of `O(|M||C|)` whole-seed combinations.
- Prior evidence probability at this boundary:
  `(|M_matched|/|M|) * (|C_matched|/|C|)`. It is **exact within
  the specified factorized prior**, not an estimate for native STS2.
- Posterior support of paired map/combat factors:
  `|M_matched| * |C_matched|` (possibly very large, not materialized).
- A new continuation costs one hypothetical reset plus one ordinary
  start_run transition, with normal future RNG correlation retained.

The pinned JSONL integration test computes the *entire small*
`M × C` joint reference prior by brute force and checks that the
factored posterior's evidence and support counts agree exactly,
while the implementation inspects only `|M| + |C|` initial
candidates. It checks all generated continuations have identical
visible frames/menus, and that the four unused random streams are
resampled rather than frozen.

## Boundaries and next steps

**Do not use this at or after the first combat, reward, shop or event.**
Those transitions can couple previously separate streams; blindly
conditioning factors independently after observing such events
would introduce fake independence and false value/variance labels.
The sampler rejects any history longer than `RunStart → MapChoice`.
A distinctive map may also collapse the finite map prior to one
supported atom. That is an inherent limitation of the selected
finite support; do not infer the native hidden seed from it.

The next extension is a **coupled posterior after a chosen map node**:
sample complete states from this verified start-of-run posterior,
execute the selected public action, and filter *jointly* on the
resulting combat/reward/event observation, preserving the streams'
actual dependencies. This can use rejection or weighted particles,
but must not falsely claim exact unbounded-prior sampling from a
finite cohort. A fully efficient native game posterior requires
its RNG distributions and conditional independence structure to
be measured and validated separately.
